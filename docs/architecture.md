# معماری و ادامه پروژه

## مرحله فعلی

Next.js 16.4.3، React 19.3.1 و TypeScript برای اجرای محلی روی Node.js 22.19 انتخاب شده‌اند. Next.js به Node.js نسخه 20.9 یا جدیدتر نیاز دارد؛ نسخه‌های نصب‌شده در `package-lock.json` تثبیت می‌شوند. [مستندات نصب Next.js](https://nextjs.org/docs/app/getting-started/installation)

صفحهٔ اصلی، هدر و هیرو، معرفی، خدمات، روش همکاری و مزایای خدمات را همراه نمونه‌کارهای منتخب، پلن‌ها و قیمت‌ها، بازخوردهای نمایشی، یادداشت‌ها، تماس، پرسش‌های متداول و فوتر نمایش می‌دهد. صفحهٔ مستقل `/portfolio/` هشت طرح نمایشی را در چهار دستهٔ طراحی سایت، مدیریت اینستاگرام، تولید محتوا و سئو نشان می‌دهد. فیلتر دسته‌ها و پنجرهٔ جزئیات طرح در مرورگر اجرا می‌شوند.

محتوای قابل ویرایش در `src/content` نگهداری می‌شود: `home.ts` برای معرفی و ارتباط؛ `portfolio.ts` برای طرح‌ها؛ `pricing.ts` برای پلن‌ها؛ `closing.ts` برای بازخوردها و پرسش‌های متداول؛ `services.ts` برای جزئیات خدمات؛ و `articles.ts` برای مجله و دسته‌های مقاله. پلن‌ها سه دسته دارند و در هر دسته سه پیشنهاد با مبلغ و دورهٔ نمایشی تعریف شده است. دادهٔ ماک و برچسب‌های «نمایشی» باید همراه هم بازبینی شوند تا هنگام جایگزینی محتوا، طرح فرضی یا قیمت آزمایشی به‌عنوان اطلاعات واقعی نمایش داده نشود.

بخش‌های ثابت، صفحهٔ مقاله و آرشیو دسته‌ها با Server Component ساخته شده‌اند. منوی موبایل، پنل‌های مزایا، فیلتر و پنجرهٔ نمونه‌کارها، انتخاب پلن، فرم تماس، جست‌وجوی مجله و اشتراک‌گذاری مقاله از Client Component استفاده می‌کنند. پنجرهٔ نمونه‌کار با `dialog` و پرسش‌های متداول با `details` پیاده شده‌اند؛ کتابخانهٔ رابط تازه‌ای اضافه نشده است.

مجله در `/blog/` هشت مقالهٔ نمونه را در چهار دسته ارائه می‌دهد. صفحهٔ هر مقاله و هر دسته با `generateStaticParams` تولید می‌شود و مسیر نامعتبر به ۴۰۴ می‌رسد. محتوای مقاله به‌صورت بخش‌های تایپ‌شده و JSX نمایش داده می‌شود و HTML خام اجرا نمی‌شود. فیلترهای مجله در نشانی با `q`، `category`، `sort` و `page` حفظ می‌شوند؛ برای دریافت آن‌ها از API مرورگر بعد از mount استفاده شده تا خروجی ایستای Pages حفظ شود. کپی لینک و اشتراک‌گذاری تنها با کلیک کاربر اجرا می‌شوند و اگر Clipboard در دسترس نباشد، لینک قابل انتخاب نمایش داده می‌شود.

فرم تماس فقط در مرورگر اعتبارسنجی می‌شود و لینک واتساپ با متن آماده می‌سازد. ارسال نهایی را خود کاربر در واتساپ انجام می‌دهد. این فرم API، ذخیره‌سازی اطلاعات یا ارسال پیام از سرور ندارد. نمونه‌کارها، بازخوردها و قیمت‌ها همگی با اعلان نمایشی مشخص‌اند و دادهٔ مشتری واقعی محسوب نمی‌شوند.

پیکربندی انتشار با `DEPLOY_TARGET=github-pages` خروجی ایستا می‌سازد و مسیر پایه را از `NEXT_PUBLIC_BASE_PATH` می‌گیرد. مسیرهای داخلی و تصاویر با تابع `sitePath` برای میزبانی زیر `/elitasocial/` آماده می‌شوند. بدون این تنظیم، اجرای معمول Next.js روی Node.js حفظ می‌شود.

## پنل مدیریت و ذخیره‌سازی

پنل اختصاصی با Next.js و ماژول داخلی `node:sqlite` پیاده شده است. API و رندر عمومی در یک برنامهٔ Node اجرا می‌شوند و سرور جداگانه‌ای لازم نیست. این انتخاب به نسخهٔ نصب‌شدهٔ Node.js 22.19 سازگار است و برای پنل یک سایت با دیسک دائمی، سرویس دیتابیس خارجی لازم ندارد. Payload و PostgreSQL در این پیاده‌سازی نصب نشده‌اند.

`src/server/database.ts` جداول کاربران، نشست‌ها، تلاش‌های ورود، رکوردهای محتوا و رسانه را ایجاد می‌کند. `content.ts` در اجرای Node، پس از `connection()` تنها رکوردهای منتشرشده را می‌خواند و داده را از طریق props به اجزای مرورگر می‌دهد. فایل‌های `src/content` دادهٔ اولیه و نوع‌های مشترک را نگه می‌دارند؛ دیتابیس هیچ‌وقت در ماژول قابل دریافت مرورگر وارد نمی‌شود. شمارهٔ نسخهٔ رکورد از بازنویسی ناخواستهٔ ویرایش هم‌زمان جلوگیری می‌کند.

هندلر مدیریت در `route.server.ts` قرار دارد. `pageExtensions` در اجرای Node پسوند `server.ts` را می‌شناسد و هنگام ساخت Pages آن را حذف می‌کند؛ بنابراین API خصوصی در خروجی ایستا وجود ندارد. دادهٔ اولیه فقط یک بار وارد SQLite می‌شود و Pages همچنان از همان داده‌های اولیهٔ فایل‌ها استفاده می‌کند. مسیرهای مقاله روی Node برای شناسهٔ تازه نیز رندر می‌شوند و به build مجدد وابسته نیستند.

احراز هویت از رمز scrypt، توکن تصادفی نشست، کوکی HttpOnly، بررسی Origin و CSRF و محدودسازی تلاش ورود استفاده می‌کند. تصاویر محدود به فرمت‌های تصویری پذیرفته‌شده، اندازهٔ فایل و ابعاد مشخص‌اند و از مسیر فایل اختصاصی سرو می‌شوند. جزئیات راه‌اندازی، حساب اولیه، دیسک دائمی و بکاپ در [راهنمای پنل](admin.md) آمده است.

## پیش از انتشار

متادیتای پیش‌نمایش عمداً `noindex` است و باید پیش از انتشار نهایی بازبینی شود. پیش‌نمایش GitHub Pages برای بازبینی طراحی است؛ دامنه نهایی باید تأیید شود. canonical، نشانی‌های Open Graph، sitemap، robots و اتصال ابزارهای تحلیل پس از مشخص شدن دامنه و تکمیل محتوای واقعی تنظیم می‌شوند. طرح‌های فرضی، قیمت‌های نمایشی و بازخوردهای ماک نیز باید با دادهٔ تأییدشده جایگزین شوند.

اسکرین‌شات‌ها و نتیجه بررسی صفحهٔ اصلی پس از اجرای `npm run check:ui` در `artifacts/ui-check` تولید می‌شوند. بررسی صفحهٔ نمونه‌کارها با `npm run check:portfolio` اجرا می‌شود. نتیجه واقعی build، بررسی TypeScript و مرورگر در گزارش تحویل ثبت خواهد شد؛ این سند ادعای قبولی اجراهای انجام‌نشده ندارد.
