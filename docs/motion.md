# حرکت و افکت‌های اسکرول

مرجع این مرحله، ویدیوی ارسالی ۲۹٫۴۵ ثانیه‌ای با اندازهٔ ۱۶۰۰×۱۲۰۰ بود. ۲۴ فریم در `artifacts/scroll-reference` استخراج و مرور شدند. لایه‌های کج‌شونده و صاف‌شوندهٔ هیرو، اختلاف سرعت تصاویر، ورود پلکانی کارت‌ها و آشکارشدن سطرهای متن، مبنای حرکت‌های صفحهٔ اصلی الیتا هستند. فایل ویدیو و فریم‌های مرجع به سایت یا Git اضافه نشده‌اند.

## اجرا در صفحهٔ اصلی

- دو لایهٔ کاغذی پشت تصویر هیرو قرار دارند و هنگام خروج هیرو از دید، به‌آرامی صاف می‌شوند.
- دو تصویر معرفی، حرکت عمودی اندک و خلاف جهت یکدیگر دارند؛ تصویر بخش روش همکاری با عمق و تغییر مقیاس اندک همراه است.
- سطرهای کامل عنوان‌های فارسی به‌ترتیب وارد می‌شوند؛ حروف و اتصال واژه‌های فارسی دست‌نخورده‌اند.
- کارت‌های خدمات و نمونه‌کارهای منتخب با چرخش جزئی و پلن‌ها، بخش تماس و دعوت انتهای صفحه با حرکت کوتاه وارد می‌شوند. مزیت‌ها به‌صورت یک گروه وارد می‌شوند تا عملکرد آکاردئون تغییر نکند.

`ScrollMotion` فقط در صفحهٔ اصلی، زیر `[data-motion-root]` نصب می‌شود. نوع ورود با `data-reveal="line|rise|image|tilt"` و ترتیب با `data-reveal-order` مشخص می‌شود. اضافه‌کردن همین ویژگی‌ها به مؤلفهٔ مشترک، به‌تنهایی در صفحه‌های دیگر افکت ایجاد نمی‌کند.

## هزینه و محدودیت‌ها

هیچ بسته یا وابستگی تازه‌ای نصب نشده است. یک `IntersectionObserver` مشترک، ورود هر هدف را یک بار اجرا و سپس آن را از مشاهده خارج می‌کند. حداکثر شش انیمیشن ورود هم‌زمان فعال‌اند؛ در پایان، خود انیمیشن لغو می‌شود تا لایهٔ آن باقی نماند. مؤلفه برای هر فریم یا اسکرول، state در React به‌روز نمی‌کند و handler اسکرول، حلقهٔ `requestAnimationFrame`، قفل اسکرول یا `MutationObserver` ندارد.

حرکت پیوستهٔ تصاویر از CSS view timeline استفاده می‌کند و به پشتیبانی مرورگر و نبود درخواست کاهش حرکت وابسته است. دسکتاپ با عرض دست‌کم ۱۰۵۰ پیکسل سطح `full` می‌گیرد؛ موبایل سطح `subtle` با ورود کوتاه‌تر و چرخش جزئی کارت‌ها، همراه حرکت محدود لایه‌های هیرو و یک تصویر معرفی دارد. صرفه‌جویی داده یا حافظهٔ گزارش‌شدهٔ حداکثر ۲ گیگابایت، سطح حداقلی را انتخاب می‌کند. تعداد پردازنده‌های منطقی دیگر معیار حذف حرکت نیست. این انتخاب‌ها به معنی اندازه‌گیری توان واقعی دستگاه یا نرخ فریم نیستند. مرورگر فاقد timeline، ورودهای یک‌باره را اجرا می‌کند و تصاویر را ثابت نشان می‌دهد.

محتوا در HTML و حالت بدون JavaScript از ابتدا دیده می‌شود. تغییر تب پلن‌ها یا داده‌های تازه، نیاز به مشاهدهٔ دوباره ندارد و موارد تازه عادی دیده می‌شوند. فوکوس، fragment و بازگشت مرورگر حرکت‌های مزاحم را پایان می‌دهند. کاهش حرکت، انیمیشن‌ها و جابه‌جایی‌های افزوده را خنثی می‌کند. بخش مدیریت، پنجرهٔ جزئیات پروژه و اجداد اصلی صفحه متحرک نشده‌اند. تصاویر متحرک حاشیهٔ مقیاس اضافی دارند تا جابه‌جایی، لبهٔ خالی نشان ندهد.

برای ویرایش حرکت‌های پیوسته، `src/app/scroll-motion.css` و برای زمان‌بندی ورودها، `src/components/scroll-motion.tsx` را تغییر دهید. [محدوده‌های timeline در MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll-driven_animations/Timeline_range_names) و [مرجع animation-range](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-range) مبنای محدوده‌های ورود و خروج‌اند.

## اصلاح دیده‌نشدن حرکت و روش بررسی

پس از گزارش کاربر، بررسی واقعی مجاز شد. انتشار قبلی به‌درستی انجام شده بود: workflow مربوط به کامیت `e030c58` در GitHub موفق بود و HTML عمومی ویژگی‌های حرکت و لایه‌های هیرو را داشت. بررسی محلی `npm run typecheck` نیز موفق شد؛ این نتایج به‌تنهایی دیده‌شدن انیمیشن را تأیید نمی‌کنند.

دو علت در بررسی رفتار قبلی مشخص شدند:

- حاشیهٔ پایین مثبت ۳۶ پیکسل در `IntersectionObserver` ورود را پیش از رسیدن هدف به دید شروع می‌کرد. هنگام اسکرول آهستهٔ ۵ پیکسل در هر ۱۱۰ میلی‌ثانیه، ورود ۴۲۰ میلی‌ثانیه‌ای پیش از دیده‌شدن هدف تمام می‌شد. حاشیهٔ پایین اکنون منفی است تا حرکت پس از ورود واقعی هدف شروع شود؛ جابه‌جایی و زمان‌بندی نیز برای دیده‌شدن همین ورود تنظیم شده‌اند.
- شرط حداکثر چهار پردازندهٔ منطقی، پارالاکس CSS را حتی در دسکتاپ چهار‌هسته‌ای غیرفعال می‌کرد. این شرط حذف شده و سطح سبک موبایل نیز حرکت محدود پیوسته دارد.

اسکریپت اختصاصی `npm run check:motion` رفتار اسکرول را از طریق Playwright بررسی می‌کند. برای هدف‌گرفتن سرور دلخواه در PowerShell:

```powershell
$env:CHECK_URL = 'http://127.0.0.1:3000'
npm run check:motion
```

برای بررسی انتشار، مقدار `CHECK_URL` را به `https://mohammadjavad-sp.github.io/elitasocial/` تغییر دهید. نتیجهٔ اجرای اصلاحات باید در [گزارش بررسی](verification.md) ثبت شود؛ صرف وجود اسکریپت یا موفقیت TypeScript، تأیید اجرای مرورگر نیست. نرخ فریم، مصرف GPU و روانی روی گوشی واقعی جداگانه به اندازه‌گیری نیاز دارند.

در مرحلهٔ نخست فقط ویدیوی مرجع با یک پخش‌کنندهٔ موقت محلی در Edge بررسی شده بود و طبق درخواست قبلی کاربر تست، build، typecheck و بررسی مرورگر پروژه اجرا نشده بودند. مجوز و بررسی مرحلهٔ اصلاح، جایگزین این محدودیت قبلی است؛ آن گزارش تاریخی، نتیجهٔ اصلاح حاضر محسوب نمی‌شود.
