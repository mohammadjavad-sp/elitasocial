# شروع سئوی نسخهٔ منتشرشده — ۱۵ نوامبر ۲۰۲۶

## وضعیت جاری — ۱۶ نوامبر ۲۰۲۶

پس از تغییر تنظیمات و build روی هاست توسط مالک، اجرای مستقل ابزار زنده صفر finding بحرانی و دو هشدار redirect داد. هفت صفحهٔ اصلی، robots، sitemap و مسیر ناموجود PASS شدند؛ noindex عمومی و نقشهٔ خالی رفع شده‌اند. تصویر کاربر ثبت Domain property در Search Console را تأیید می‌کند؛ ثبت sitemap و URL Inspection مرحلهٔ بعدند. گزارش اولیهٔ ۱۵ نوامبر در پایین تاریخچه است؛ رفع مانع فنی، تضمین یا اثبات ایندکس و رتبه نیست.

در هاست، affinity ترمینال `0-87` و حضور یک فرایند ۵۱تردی مشاهده شد. محدودکردن فرمان‌های ساخت به CPUهای مجاز ۰ و ۱ از `EAGAIN` مرحلهٔ TypeScript عبور کرد. خطای بعدی worker از گزینهٔ `--v8-pool-size` بود. probe نشان داد حتی با مقدار خالی در shell این گزینه در محیط اجرای Node وجود داشت؛ پس از حذف ردیف `NODE_OPTIONS` از Environment variables پنل، probe نبود آن را تأیید و build کامل شد. بنابراین فقط unset/export در shell جای حذف آن ردیف ناسازگار پنل را نمی‌گیرد. در کامپیوتر/هاست دیگر، ابتدا CPUهای واقعاً مجاز بررسی شوند؛ ماسک ۰ و ۱ یک پیش‌فرض عمومی نیست.

هدف تجاری اعلام‌شده: جذب درخواست برای همهٔ خدمات، با اولویت طراحی سایت و ادمینی اینستاگرام. شهر هدف هنوز تعیین نشده است؛ فعلاً ادعای دفتر یا خدمت محلی برای شهر مشخصی نمی‌سازیم. در آغاز ممیزی Search Console ثبت نشده بود؛ بعداً تصویر ثبت آن ارائه شد. این سند برنامهٔ اجراست، نه وعدهٔ رتبه یا گزارش افزایش مشتری.

## نتیجهٔ مشاهدهٔ مستقیم

در ۱۵ نوامبر ۲۰۲۶، درخواست‌های عمومی GET با Node fetch و اعتبارسنجی عادی TLS، بدون ورود به پنل یا خواندن env/دیتابیس اجرا شدند. ابزار مرور وب نتوانست دامنه را باز کند؛ دریافت HTTP مستقل موفق بود. این بررسی معادل مشاهدهٔ وضعیت ایندکس در حساب گوگل یا اجرای Googlebot نیست.

| مورد | نتیجهٔ مشاهده‌شده | اولویت |
| --- | --- | --- |
| `https://elitasocial.ir/` | پاسخ ۲۰۰ و HTML خود سایت؛ `robots=noindex, nofollow` | رفع مانع ایندکس |
| `/sitemap.xml` | پاسخ ۲۰۰ و `urlset` خالی | پس از فعال‌سازی ایندکس دوباره بررسی شود |
| `/robots.txt` | خزش عمومی مجاز، پنل/API محدود، بدون معرفی sitemap | نتیجهٔ تنظیم ایندکس فعلی |
| canonical و OG صفحهٔ اصلی | دامنهٔ HTTPS اصلی و تصویر اشتراک‌گذاری موجودند | حفظ شوند |
| `http://elitasocial.ir/` | پاسخ مستقیم ۲۰۰، بدون redirect | انتقال دائمی به HTTPS |
| `https://www.elitasocial.ir/` | پاسخ مستقیم ۲۰۰، بدون redirect | انتقال دائمی به دامنهٔ بدون www |
| دادهٔ ساختاریافتهٔ صفحهٔ اصلی | اسکریپت JSON-LD مشاهده نشد | مرحلهٔ بعد؛ مانع ایندکس نیست |

بررسی تکمیلی ابزار روی هفت صفحهٔ خانه، چهار خدمت، پلن‌ها و مجله، noindex همه را تأیید کرد؛ canonicalها و یکتایی عنوان/توضیح آن‌ها معتبر بودند. صفحهٔ ناموجود نیز ۴۰۴/noindex بود. فرمان‌های آزمون موجود و ابزار تازه مجموعاً ۲۵ آزمون محلی موفق داشتند؛ اجرای زنده تا رفع تنظیم هاست عمداً ناموفق است.

پیام `noindex` علت قابل اثبات جلوگیری از ایندکس است. وجود canonical به‌تنهایی آن را خنثی نمی‌کند. از این بررسی نمی‌توان تعداد URLهای ایندکس‌شده، رتبه، حجم جست‌وجو یا نرخ تبدیل فعلی را نتیجه گرفت.

## مرحلهٔ اول: بازکردن ایندکس روی هاست

این تغییر در تنظیمات **هاست** انجام می‌شود، نه فایل محلی کامپیوتر. نسخهٔ Node سایت قبلاً ساخته و توسط کاربر فعال‌شدنش تأیید شده است. safe default پیش‌نمایش و GitHub Pages باید noindex باقی بماند؛ رفتار محافظتی کد را حذف نکنید.

در Setup Node.js App → Environment variables، مقدار موجود را ویرایش یا نام غایب را اضافه کنید؛ برای یک نام، ورودی تکراری نسازید:

```text
SITE_URL=https://elitasocial.ir
SITE_INDEXING=true
```

متغیرهای پنل بر `.env.local` هاست اولویت دارند. برای جلوگیری از اختلاف تنظیمات، مقادیر متناظر در فایل خصوصی هاست نیز توسط مالک هماهنگ شوند؛ فایل/رمزها در چت، Git یا screenshot منتشر نشوند. اگر از Terminal برای build استفاده می‌شود، دو مقدار عمومی بالا را صریحاً در همان subshell export کنید؛ نباید فرض شود محیط ترمینال الزاماً همهٔ متغیرهای Passenger را دریافت کرده است.

پس از Save، با توجه به سهمیهٔ محدود فرایند/فضای حساب، فقط یک build و با همان پروفایل موفق هاست انجام شود. پیش از شروع، فضای آزاد و امکان ورود به ترمینال بررسی شوند. تغییر metadata ایستا و sitemap خاموشِ prerenderشده با Restart تنها تضمین نمی‌شود؛ rebuild لازم است. نمونهٔ فرمان پس از فعال‌کردن محیط Node خود برنامه:

```bash
(
set -e
cd /home/gzhutfvg/elita-social
export SITE_URL=https://elitasocial.ir SITE_INDEXING=true
unset DEPLOY_TARGET NEXT_PUBLIC_BASE_PATH
export NODE_OPTIONS=""
export CPANEL_LOW_RESOURCE_BUILD=true UV_THREADPOOL_SIZE=1 RAYON_NUM_THREADS=1
taskset -c 0,1 node scripts/prepare-images.mjs
taskset -c 0,1 node node_modules/next/dist/bin/next build --webpack
taskset -c 0,1 node node_modules/typescript/bin/tsc --noEmit
echo SEO_BUILD_OK
)
```

این فرمان نیازی به نصب مجدد، migration یا `cms:init` ندارد. پاک‌سازی دیتابیس/رسانه لازم نیست. پس از موفقیت، برنامه از پنل یک بار Start/Restart شود. برای به‌روزرسانی همان Application root باید وقفهٔ کوتاه سرویس در نظر گرفته شود؛ این روش انتشار اتمیک نیست. در صورت خطای build، موفقیت اعلام نشود و فرایندها/نصب چندباره تکرار نشوند.

معیار پذیرش پس از راه‌اندازی:

- خانه و صفحات خدمات پاسخ ۲۰۰ بدهند و هیچ meta robots/googlebot یا X-Robots-Tag مؤثر حاوی `noindex` یا `none` نباشد.
- sitemap غیرخالی، فقط شامل مسیرهای عمومی منتشرشده باشد و در robots معرفی شود.
- پنل و صفحات ناموجود همچنان noindex باشند؛ مسیر ناموجود واقعاً ۴۰۴ بدهد.
- canonical و لینک‌های داخلی روی HTTPS دامنهٔ اصلی باشند؛ نسخه‌های HTTP و www با انتقال دائمی مسیر و query را حفظ کنند.

برای بررسی بدون دسترسی خصوصی از کامپیوتر توسعه اجرا شود:

```bash
npm run check:seo:live
```

ابزار عمومی HTTP شاخص‌های اولیه را می‌سنجد؛ جای گزارش Google Search Console یا بررسی دستی محتوای صفحات را نمی‌گیرد. موفقیت این فرمان در ۱۶ نوامبر تأیید شد؛ تغییرات بعدی نیازمند بررسی مجدد خودشان هستند.

## مرحلهٔ دوم: تأیید مالکیت و معرفی صفحات به گوگل

1. در [Search Console](https://search.google.com/search-console)، با حساب تحت مالکیت کسب‌وکار، Domain property برای `elitasocial.ir` بسازید (بدون پروتکل و مسیر).
2. مقدار TXT ارائه‌شده توسط گوگل را در DNS معتبر دامنه اضافه کنید. Zone Editor سی‌پنل فقط در صورتی مؤثر است که nameserverهای دامنه از همان DNS استفاده کنند. رکوردهای موجود، به‌ویژه ایمیل، حذف نشوند. مقدار تأیید مالکیت عمومی است؛ رمز حساب و دسترسی cPanel لازم نیست به چت فرستاده شوند.
3. پس از Verify و رفع noindex، در Sitemaps، `https://elitasocial.ir/sitemap.xml` را ثبت کنید.
4. با URL Inspection و Test Live URL، صفحهٔ اصلی و دو صفحهٔ `/services/website` و `/services/instagram` را بررسی و درخواست ایندکس کنید. ارسال sitemap و درخواست ایندکس تضمین ورود یا زمان ورود به نتایج نیستند.
5. بخش Pages، Manual actions و Security issues بررسی شوند. baseline شامل تاریخ اتصال و وضعیت پذیرش sitemap ثبت شود؛ در این مرحله هیچ آمار ساختگی از Search Console نداریم.

## مرحلهٔ سوم: بهبود صفحات جذب پروژه

عبارت‌های زیر فرضیهٔ اولیهٔ نیت جست‌وجو هستند، نه نتیجهٔ ابزار حجم جست‌وجو یا سنجش رقبا. URLهای موجود حفظ شوند تا تغییر عنوان یا متن، لینک‌های منتشرشده را نشکند.

| صفحه | نیت اصلی پیشنهادی | کاری که محتوا باید انجام دهد |
| --- | --- | --- |
| `/` | الیتا سوشیال، الهه طاهری و معرفی مجموعهٔ خدمات | روشن‌کردن هویت، خدمات و مسیر درخواست مشاوره |
| `/services/website` | خدمات طراحی سایت، طراحی سایت شرکتی/خدماتی | تعریف خروجی، دامنهٔ امکانات، مراحل، مدیریت محتوا، تحویل و هزینه‌های مستقل دامنه/هاست |
| `/services/instagram` | ادمینی اینستاگرام، مدیریت پیج اینستاگرام | شرح مسئولیت‌ها، تقویم، پست/استوری/ریلز، پاسخ‌گویی، گزارش و موارد خارج از قرارداد |
| `/pricing` | تعرفهٔ طراحی سایت و قیمت ادمینی پیج | مقایسهٔ پلن‌ها، هزینهٔ پروژه‌ای/ماهانه، محدودیت‌ها و شرایط واقعی تأییدشده توسط مالک |
| `/services/seo` | خدمات سئو سایت | روند ممیزی، اجرا و سنجش نتیجه؛ بدون تضمین رتبه |
| `/services/content` | خدمات تولید محتوا | قالب، خروجی و چرخهٔ بازبینی/تأیید |

اول متن‌های موجود CMS و صحت قیمت‌ها از پنل بازبینی شوند؛ تغییر فایل starter به‌تنهایی محتوای فعلی دیتابیس را عوض نمی‌کند. برای بهینه‌سازی، دادهٔ واقعی مالک بازنویسی یا seed مجدد نشود. نمونه‌کارها طبق تصمیم قبلی فقط به پیج `elita.nasl` ارجاع می‌شوند؛ گالری یا نظرات ساختگی اضافه نمی‌شود.

برنامهٔ محتوای اولیه با تمرکز بر پرسش پیش از خرید:

- هزینهٔ طراحی سایت از چه بخش‌هایی تشکیل می‌شود؟ لینک به خدمت طراحی و پلن‌ها؛ مبلغ بدون تأیید مالک قطعی اعلام نشود.
- برای سفارش سایت چه اطلاعاتی آماده کنیم؟ ابتدا مقاله‌های موجود، از جمله محتوای brief، بازبینی شوند تا مطلب تکراری ساخته نشود.
- ادمین اینستاگرام دقیقاً چه کارهایی انجام می‌دهد؟ مرزبندی تولید، انتشار و پاسخ‌گویی؛ لینک به صفحهٔ ادمینی.
- چطور پلن مدیریت پیج را انتخاب کنیم؟ معیار حجم محتوا و مسئولیت‌ها، با لینک به دستهٔ پلن مربوط.

پس از اندازه‌گیری، فقط موضوع‌های دارای ارزش برای مشتری توسعه یابند. صفحه‌های شهری تکراری، خرید بک‌لینک انبوه، وعدهٔ فروش و تکرار مصنوعی کلمات در برنامه نیستند.

## مرحلهٔ چهارم: دادهٔ ساختاریافته و اندازه‌گیری

در کار بعدی، Organization/WebSite برای برند، BreadcrumbList برای صفحات دارای مسیر راهنما و BlogPosting برای مقاله، با استفاده از محتوای واقعاً نمایش‌داده‌شده طراحی شوند. آدرس دفتر، امتیاز، نظر مشتری، سابقه، تاریخ انتشار و قیمت ساختگی وارد schema نشوند. نبود JSON-LD مانع crawl/index نیست و اضافه‌کردن آن تضمین rich result یا رتبه نمی‌دهد.

از Search Console، کلیک/نمایش/عبارت و صفحهٔ ورودی به‌صورت دوره‌ای بررسی شوند. برای تصمیم تجاری، نرخ درخواست مشاورهٔ معتبر و کلیک ارتباطی نیز با ابزار اندازه‌گیری و سیاست حریم خصوصی مشخص لازم‌اند. هیچ Analytics/tracker یا رویداد حاوی نام، شماره، متن پیام و ایمیل در این مرحله نصب/ارسال نشده است.

## حدود انجام این مرحله

ممیزی عمومی و آماده‌سازی ابزار/راهنما انجام شده‌اند. متغیرهای هاست، DNS، اتصال حساب Search Console، محتوای CMS و وضعیت ایندکس گوگل مستقیماً تغییر نکرده‌اند. مرحلهٔ بعد به اقدام مالک در پنل هاست و حساب گوگل وابسته است؛ بعد از تغییر باید دوباره پاسخ زنده سنجیده شود.
