# ارسال درخواست مشاوره به ایمیل

مقصد اولیه `elitasociall@gmail.com` است و از «تنظیمات سایت ← برند و ارتباط ← ایمیل» قابل تغییر است. نشانی، عمومی و همان ایمیل دکمه‌های تماس است؛ رمز جیمیل، App Password یا کلید SMTP در کد یا مرورگر قرار نمی‌گیرد. برای این اتصال پکیج یا متغیر محیطی تازه‌ای لازم نیست.

## فعال‌سازی مقصد

سایت برای ارسال فرم از [FormSubmit و روش AJAX رسمی](https://formsubmit.co/ajax-documentation) استفاده می‌کند. طبق [راهنمای رسمی راه‌اندازی](https://formsubmit.co/#setup)، اولین ارسال فرم ایمیل تأیید به مقصد می‌فرستد. صاحب سایت باید پیام FormSubmit را در Inbox یا Spam پیدا کند و لینک فعال‌سازی آن را بزند. تا قبل از این تأیید، دریافت درخواست‌های واقعی در صندوق ایمیل آماده نیست. بعد از فعال‌سازی، یک درخواست آزمایشی از همان سایت منتشرشده بفرستید و دریافت آن را در جیمیل بررسی کنید. تغییر مقصد ایمیل نیز به تأیید مقصد تازه نیاز دارد.

آزمون‌های خودکار این پروژه با دادهٔ ساختگی و fetch یا شبکهٔ شبیه‌سازی‌شده انجام می‌شوند؛ هیچ ایمیلی به صندوق واقعی ارسال نکرده‌اند و دریافت در Gmail را تأیید نمی‌کنند.

## مسیر درخواست

- روی GitHub Pages، مرورگر فرم معتبر را با HTTPS و JSON مستقیم به `https://formsubmit.co/ajax/{email}` می‌فرستد. دیتابیس یا کد پیگیری ساختگی وجود ندارد.
- روی Node، ابتدا API خود سایت درخواست را با اعتبارسنجی سرور در SQLite ثبت و کد پیگیری صادر می‌کند. تنها بعد از ثبت موفق، مرورگر نسخه‌ای را برای ایمیل می‌فرستد. شکست ثبت، ایمیل ارسال نمی‌کند.
- شکست ایمیل پس از ثبت، درخواست و کد پیگیری را حفظ می‌کند. «تلاش دوباره برای ارسال ایمیل» فقط همان پیام ذخیره‌شده در حافظهٔ صفحه را دوباره به سرویس می‌فرستد؛ درخواست تازه‌ای در پنل نمی‌سازد. با بستن صفحه، دادهٔ تلاش مجدد در مرورگر باقی نمی‌ماند، اما درخواست ثبت‌شده در پنل محفوظ است.
- پیام موفقیت صرفاً پذیرش درخواست توسط سرویس ایمیل را تأیید می‌کند؛ تضمین رسیدن به Inbox یا خوانده‌شدن پیام نیست. قطعی سرویس، محدودیت آن، فعال‌نشدن مقصد و فیلترهای ایمیل می‌توانند مانع دریافت شوند. این اتصال صف پایدار یا ارسال پس‌زمینهٔ سرور ندارد؛ پنل Node مرجع پیگیری درخواست‌های ثبت‌شده است.
- بدون JavaScript، فرم با POST به صفحهٔ سرویس ارسال می‌شود و کاربر از سایت خارج می‌شود. این مسیر در دیتابیس Node ثبت نمی‌کند و به اعتبارسنجی مرورگر و سرویس وابسته است؛ اطلاعات فرم با GET در URL قرار نمی‌گیرد.

نام، راه ارتباطی، خدمت، متن، پلن انتخابی و کد پیگیری در صورت وجود به سرویس ارسال می‌شوند. متن کنار فرم استفاده از سرویس بیرونی و وضعیت ذخیره در سایت را توضیح می‌دهد. مقدار Reply-To فقط زمانی ارسال می‌شود که کاربر ایمیل معتبر داده باشد؛ شمارهٔ موبایل به‌عنوان ایمیل استفاده نمی‌شود. فیلد ضدربات `_honey` حفظ شده و خاموش‌کردن CAPTCHA درخواست نمی‌شود. متن آمادهٔ واتساپ و راه‌های ارتباطی دیگر همچنان اختیاری‌اند.

مهلت پاسخ سرویس ۲۰ ثانیه است. پاسخ ناموفق HTTP، JSON نامعتبر، `success: false` و پاسخ بدون موفقیت صریح خطا محسوب می‌شوند؛ متن خام سرویس وارد پیام رابط نمی‌شود. عدم دریافت پاسخ ممکن است پس از پذیرش سرویس رخ دهد؛ تلاش مجدد ایمیل در چنین حالتی احتمال ایمیل تکراری دارد و ادعای ارسال دقیقاً یک‌باره وجود ندارد.

آزمون متمرکز بدون شبکهٔ واقعی:

```sh
node --import tsx --test scripts/check-consultation-email.test.ts
```
