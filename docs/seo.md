# سئوی فنی و انتشار

متادیتای همهٔ صفحه‌های عمومی، canonical، Open Graph و Twitter Card از یک تنظیم مشترک دامنه ساخته می‌شوند. عنوان و توضیح هر صفحه مستقل است؛ عنوان و توضیح صفحهٔ اصلی از تنظیمات سایت خوانده می‌شود. مقاله‌ها و جزئیات خدمات، تصویر خودشان را دارند و صفحه‌های عمومی دیگر از `public/images/social-share.jpg` با ابعاد ۱۲۰۰×۶۳۰ استفاده می‌کنند. این JPEG برند، حدود ۹۹ کیلوبایت است و با `node scripts/prepare-social-preview.mjs` بازتولید می‌شود.

## تنظیم دامنه و ایندکس

در محیط هاست Node و **پیش از build**:

```dotenv
SITE_URL=https://your-final-domain.ir
SITE_INDEXING=true
```

`SITE_URL` فقط مبدأ کامل سایت است؛ مسیر، نام کاربری، پارامتر یا fragment ندارد. برای مثال `https://your-final-domain.ir` معتبر است. مسیر نصب احتمالی فقط از `NEXT_PUBLIC_BASE_PATH` اضافه می‌شود. نام دامنهٔ این مثال باید با دامنهٔ تأییدشده جایگزین شود و تغییر این تنظیمات پس از build به build و راه‌اندازی دوباره نیاز دارد.

ایندکس تنها با `SITE_INDEXING=true`، حالت production، دامنهٔ صریح عمومی و HTTPS فعال می‌شود. پیش‌فرض، محیط توسعه، localhost/IP، دامنه‌های پیش‌نمایش و خروجی GitHub Pages همیشه `noindex, nofollow` هستند. workflow فعلی، مبدأ پیش‌نمایش GitHub و `SITE_INDEXING=false` را صریح تنظیم می‌کند. برای پیش‌نمایش بدون تنظیم دامنه، canonical اجرای محلی از localhost و خروجی Pages از نشانی GitHub ساخته می‌شود؛ دامنهٔ واقعی حدس زده نمی‌شود.

پنل مدیریت و صفحه‌های پیدا‌نشده، مستقل از تنظیم عمومی `noindex` می‌مانند. metadata صفحات ناموجود، به صفحهٔ اصلی canonical نمی‌دهد؛ `notFound()` اجرا می‌شود. پارامترهای جست‌وجو، فیلتر، UTM و fragment وارد canonical، OG URL یا نقشهٔ سایت نمی‌شوند. اسلش انتهای canonical با رفتار مسیرها هماهنگ است: روی Node حذف و در Pages حفظ می‌شود؛ مسیر فایل‌ها مانند تصویر و XML اسلش اضافه نمی‌گیرد.

## نقشهٔ سایت و robots

- `/sitemap.xml` فقط هنگام فعال‌بودن ایندکس، صفحهٔ اصلی، خدمات، نمونه‌کارها، پلن‌ها، مجله، خدمات منتشرشده، مقالات منتشرشده و دسته‌های دارای مقاله را فهرست می‌کند.
- پیش‌نویس، محتوای حذف‌شده، پنل، API و URLهای دارای query یا fragment وارد نقشه نمی‌شوند. روی Node در حالت انتشار ایندکس‌پذیر، تغییر وضعیت محتوا در درخواست بعدی نقشه اعمال می‌شود؛ build مجدد برای انتشار مقاله لازم نیست.
- تاریخ `lastmod` ساخته نشده است؛ مدل فعلی محتوا تاریخ واقعی انتشار/ویرایش عمومی ندارد. تاریخ build به‌جای تاریخ تغییر مقاله قرار نمی‌گیرد.
- وقتی ایندکس غیرفعال است، نقشهٔ سایت عمداً خالی است و robots آن را به موتور جست‌وجو معرفی نمی‌کند.
- `/robots.txt` خزش صفحه‌های عمومی و فایل‌های CSS/JS/تصویر را مجاز می‌گذارد تا موتور جست‌وجو بتواند `noindex` را بخواند. پنل و API محدودند؛ مسیر عمومی `/api/cms/files/` برای تصاویر منتشرشده استثنا است. این فایل جای احراز هویت پنل را نمی‌گیرد.

در GitHub project Pages، فایل تولیدشده در `/elitasocial/robots.txt` در ریشهٔ مبدأ `mohammadjavad-sp.github.io` نیست؛ کنترل robots آن مبدأ در اختیار این مخزن نیست. جلوگیری از ایندکس این پیش‌نمایش بر تگ `noindex` هر صفحه تکیه دارد. هنگام استقرار Node در دامنهٔ اصلی، `/robots.txt` و `/sitemap.xml` در ریشهٔ همان دامنه در دسترس خواهند بود.

## تأیید انتشار

`npm run check:seo` با داده و SQLite مستقل، قواعد دامنه، ایندکس، canonical، تصویر اشتراک‌گذاری و انتشار/پیش‌نویس/حذف مقاله را بررسی می‌کند؛ اطلاعات واقعی و رمزها خوانده نمی‌شوند. برای استقرار نهایی، پس از تنظیم متغیرها build بگیرید و canonical چند صفحه، تصویر اشتراک‌گذاری، robots و XML را از دامنهٔ واقعی بررسی کنید؛ سپس نشانی نقشهٔ سایت را در Search Console ثبت کنید. عنوان/توضیح در پیام‌رسان‌ها ممکن است با تأخیر ناشی از کش آن سرویس به‌روز شوند.

مرجع رفتار: [متادیتای Next.js](https://nextjs.org/docs/app/api-reference/functions/generate-metadata)، [راهنمای noindex گوگل](https://developers.google.com/search/docs/crawling-indexing/block-indexing)، [راهنمای canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) و [نقشهٔ سایت گوگل](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).
