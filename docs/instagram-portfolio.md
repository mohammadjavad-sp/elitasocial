# انتقال تمام نمونه‌کارها به اینستاگرام — ۱۵ نوامبر ۲۰۲۶

طبق آخرین درخواست مالک، صفحه و گالری داخلی نمونه‌کارها به‌طور کامل حذف شدند. نمونه‌های ادمینی اینستاگرام، طراحی سایت، سئو و تولید محتوا همگی از طریق پیج `https://www.instagram.com/elita.nasl/` معرفی می‌شوند. این تصمیم جایگزین تغییر قبلیِ حذف صرفاً نمونه‌های اینستاگرام است.

## تغییرات

- `src/app/portfolio/page.tsx`، گالری، پیش‌نمایش‌های ساختگی، دیالوگ جزئیات، داده‌های اولیه و CSS اختصاصی گالری حذف شدند.
- `src/components/portfolio-invitation.tsx` و `src/app/portfolio-invitation.css` بخش جایگزین صفحهٔ اصلی را می‌سازند: معرفی کوتاه، چهار حوزهٔ کاری و یک لینک مستقیم پیج، با رنگ‌های برند و ظاهر روشن/تاریک. این بخش Server Component است؛ iframe، دریافت محتوای اینستاگرام، تصویر تازه یا وابستگی جدید ندارد.
- `src/components/portfolio-preview.tsx` تنظیمات قابل ویرایش پنل را به بخش جدید می‌دهد. شناسهٔ `#portfolio` برای لینک‌های قبلی صفحهٔ اصلی حفظ شده است.
- ورودی صفحهٔ نمونه‌کار از منوی هدر و sitemap حذف شد. لینک‌های هیرو، فوتر و تمام صفحات خدمات به پیج می‌روند.
- در Node، تنظیم `redirects` در `next.config.ts` آدرس قدیمی `/portfolio` را با ۳۰۸ به `/#portfolio` هدایت می‌کند. Pages از این تنظیم سروری استفاده نمی‌کند؛ در خروجی static صفحهٔ قدیمی وجود ندارد.
- `src/server/content.ts` دیگر نمونه‌کارها را از CMS نمی‌خواند یا به UI عمومی نمی‌فرستد. `src/server/seed.ts` نیز برای نصب تازه، نمونه‌کار ساختگی ایجاد نمی‌کند.
- بخش نمونه‌کار از مجموعه‌های فعال، منو، آمار، ویرایشگر و API مدیریت حذف شد. رکوردهای قدیمی بدون حذف یا reset در دیتابیس می‌مانند؛ مقدار تاریخی `portfolio` در constraint دیتابیس فقط برای سازگاری دادهٔ قبلی حفظ شده است. migration لازم نیست.
- اشاره‌های اضافی در امکانات پلن‌ها و متن مقالات اصلاح شدند؛ adapter نمایش فقط متن‌های اولیهٔ دقیقاً همسان را برای رکوردهای قبلاً ذخیره‌شده اصلاح می‌کند و نوشته‌های اختصاصی و اطلاعات دیگر را حفظ می‌کند. استایل بلااستفادهٔ پس‌زمینهٔ صفحهٔ قدیمی هم حذف شد.
- فیلدهای تنظیمات معرفی و دکمه حفظ شدند؛ متن‌های اولیهٔ قدیمی به متن دعوت جدید ارتقا می‌یابند و متن اختصاصی مالک بازنویسی نمی‌شود.
- استایل‌ها و انتخابگرهای تعامل/انیمیشن گالری قدیمی از CSS مشترک پاک شدند؛ رفتار مجله، خدمات و پلن‌ها حفظ شده است.
- `tsconfig.json` پوشه‌های خروجی `artifacts` و `out` را از بررسی سورس کنار می‌گذارد. پیش از این، کپی‌های قدیمی پروژه و اسکریپت‌های موقتِ ignored داخل artifacts هم typecheck می‌شدند و پس از حذف گالری، به APIهای حذف‌شده ارجاع می‌دادند.

## بررسی‌ها و حدود آن‌ها

- `next typegen` و `npm run typecheck`: موفق. typegen ارجاع تولیدشده به route حذف‌شده را تازه کرد.
- `node --import tsx --test scripts/check-portfolio-content.test.ts`: چهار آزمون موفق؛ خروجی HTML بدون JS، حفظ متن اختصاصی، منو، seed، مجموعه‌های فعال، تنظیم redirect و اصلاح متن‌های قدیمی بدون تغییر ورودی.
- `npm run check:security`: ۳۳ آزمون موفق در محیط موقت مستقل؛ شامل غیرفعال بودن CRUD نمونه‌کار، نبودن آن در آمار و حفظ رکورد قدیمی.
- بررسی تکمیلی مرورگر در مرحلهٔ پاک‌سازی: متن هشت مقاله و امکانات پلن طراحی سایت بدون اشاره‌های قبلی بود؛ لینک دعوت صفحهٔ اصلی صحیح ماند. منو و پیشخوان پنل با نشست و پاسخ آمار شبیه‌سازی‌شده بررسی شدند و بایگانی نمایش داده نشد. در آزمون پنل، نشست واقعی مدیر استفاده نشد و درخواست‌های مدیریتی به دیتابیس واقعی نرفتند.
- `npm run check:seo`: ۱۵ آزمون موفق؛ sitemap دیگر صفحهٔ حذف‌شده را ندارد. دیتابیس این بررسی‌ها موقت و مستقل از اطلاعات واقعی سایت است.
- `npm run check:portfolio`: هشت حالت موفق، چهار عرض ۱۴۴۰، ۷۶۸، ۳۹۰ و ۳۲۰ در هر دو تم؛ بدون گالری/دیالوگ/لینک داخلی بازنشسته، دسترسی کیبورد، لینک چهار صفحهٔ خدمت، هیرو و فوتر، عدم سرریز افقی و redirect واقعی ۳۰۸ سرور محلی. تصاویر دسکتاپ روشن/تاریک و موبایل روشن بازبینی شدند.
- اسکریپت `check:ui` با بخش جدید سازگار شد؛ مجموعهٔ کامل آن در این مرحله اجرا نشده است.
- خروجی‌های مرورگر در `artifacts/portfolio-invitation-check/` از Git مستثنا هستند. `git diff --check` موفق است.

## انتشار

این تغییرات در سورس محلی آماده‌اند. build تازهٔ production، push و استقرار روی هاست در این مرحله انجام نشده‌اند. برای حذف کامل route، انتشار باید حذف فایل‌ها را هم اعمال کند؛ کپی‌کردن صرفِ فایل‌های جدید روی پوشهٔ قدیمی هاست، فایل `src/app/portfolio/page.tsx` را حذف نمی‌کند. پس از انتشار سورس، build و Restart برنامه لازم است؛ `.env.local`، مسیر داده و رسانه‌ها باید حفظ شوند. `cms:init` یا حذف داده‌ها لازم نیست.
